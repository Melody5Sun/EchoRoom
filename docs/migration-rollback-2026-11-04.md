# 本地库存迁移与回滚契约验证

MigrationRollbackIntegrationTest 在独立 MySQL 8.4 测试容器的四个独立 schema 中通过四项真实集成测试，不访问本机既有业务库。完整 Java 门禁 57 项零失败/零跳过；六类真实集成报告共 13 项，均要求本轮新生成。

验证范围：

1. V7 数据库中的 PENDING/SUCCESS 回填预占；CLOSED/FAILED 不占库存。升级到 V9 后，既有订单、钱包、流水和 Outbox 行保持不变。
2. 预检 SQL 返回历史超卖活动清单，此时尚未执行 V8 DDL，订单不变。
3. 绕过预检时 V8 的 CHECK 阻断超卖，但 MySQL 已执行的加列、回填不会整体回滚。测试明确确认失败历史及保留下来的订单，不把失败包装为成功升级。
4. 应用回滚到旧写入契约后，模拟旧版本插入订单而不维护预占。Flyway 不会再次执行 V8；停写重算使计数与订单恢复一致。任一活动超卖时，重算 SQL 整条失败，其他活动也不会部分更新，订单保留。

重算脚本为 scripts/recount-inventory.sql。要求 V8 已成功、CHECK 仍生效，所有旧/新活动写入均停止且在途请求已排空。必须先检查 preflight-inventory.sql 并保存异常清单；不得用重算脚本盲修部分失败的 V8 或删除历史订单。

上述四项测试模拟旧版本的数据库写入契约，实际二进制续验见下节。真实多机发布、备份恢复和生产入口切换仍须在目标环境独立验收。

## 实际二进制续验
