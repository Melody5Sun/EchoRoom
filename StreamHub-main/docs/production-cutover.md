# 生产切换、回滚与异机验收

本手册的本地演练入口见 [HA 演练](../infra/ha/README.md)。生产操作要使用预生产复现过的版本、备份工具和发布流水线；不把演练 Compose 和其中的账号、网络或卷直接搬到生产。当前仓库没有已配置的外部部署目标，以下异机验收需要在实际目标执行并保存证据。

## 部署和切换准备

| 组件 | 必备条件 | 放行证据 |
|---|---|---|
| 入口与应用 | API、Realtime 和 Live 至少各两实例，跨主机分布；外部负载均衡也具备冗余。HTTPS 终止，WebSocket 升级与排空经过验证；只信任实际直连代理的 IP，代理覆盖外部转发头。 | 从外网经两条入口分别请求、取 Ticket 和收到 CONNECTED；摘除一条路径后新请求与重连成功，伪造代理头无效。 |
| MySQL | 三个故障域中的单主集群；应用和 Nacos 使用私网冗余 Router 地址与独立库权限；迁移和只读监控使用各自账号。 | Router 指向同一个可写主，备用路径可写入探针库；数据库全量备份和日志恢复已在隔离实例核验。 |
| Redis | 一主两副本、三个 Sentinel，服务可达 Sentinel 宣告的实际节点地址。应用与管理分别授权，验证认证和加密传输。 | 切换时拒绝新增交易/弹幕，已建连接可心跳，切换后确认新主、恢复 Presence、订阅与跨节点限流；活动对账完成再解除保护。 |
| RocketMQ / Nacos | Controller 和 Nacos 仲裁实例跨三个故障域，NameServer 与 Broker 副本跨主机。Broker 同步复制和刷盘，保持双副本确认。 | 任一 Broker 掉线时 Outbox 保留待投递；副本恢复后送达并核对唯一流水。Nacos 单节点不可达时既有调用和新发现可用。 |
| SRS | 双源站和备用推流地址，外部播放入口有冗余。HTTP-FLV/HLS 使用边缘分发；WebRTC 单独验证公网 ICE/UDP 可达和备用源站重新信令。 | 真实推流端按备用地址恢复，播放器重建会话；分别记录媒体空窗与首帧恢复时间。 |

部署前在相同数据库参数上运行 [连接预算检查](../scripts/check-db-budget.ps1)。把滚动发布临时多出的实例计入最大副本数；应用连接、迁移、Router/Nacos、监控和运维连接的预算合计不超过 MySQL 上限的 80%。同时核对 HTTP 和 MQ 消费并发、JVM、容器限制与应用版本。登记发布前阈值、操作者、回退时间界限和证据目录。

## 应用发布

1. 先将入口限流发布为观察模式，确认可信代理和真实用户归属，再按入口逐批开启拒绝。记录 429、503、事务及连接池趋势；缓存和异步发送独立开关。发生系统错误增长、订单超时或资源持续堆积时暂停下一批。
2. 房间频道先让全部 Live 节点运行 `dual-legacy`；确认双订阅健康后逐台变更为 `dual-room`；最后在所有发布者已切到房间频道后切至 `room`。过渡期间只发布一个频道。每一段用跨节点弹幕、历史补偿及无观众节点的订阅状态验收。回滚按 `room → dual-room → dual-legacy → 旧版本` 执行，每一步全量完成后再切下一步。
3. 库存迁移单独开窗。关闭秒杀入口并排空写入、确认没有旧写者；保存活动、订单、流水和 Outbox 基线并完成备份。执行 [V8 预检查](../scripts/preflight-inventory.sql)，异常清单非空即停止。迁移后核对预占计数、真实待处理订单与 Redis 的重建结果，再放少量业务流量。详见 [迁移和回滚验证](migration-rollback-2026-11-04.md)。
4. 代码回滚保留新增列、约束和索引。回到旧写入逻辑期间不开放秒杀；重新升级前停止旧写者、重新执行预检查和原子 recount，然后重建 Redis 活动数据。不能以回滚 Flyway 记录、删除列或重置库存掩盖差异。

## 基础设施切换与回滚

1. 使用隔离目标完成数据库备份恢复、GTID 进度核验、MQ 消费位点与消息保留窗口核对、配置及证书恢复；记录实测恢复耗时。先校验业务库和 Nacos 库，另存应用 JAR/镜像摘要与当前入口/Router 地址。
2. 切换前停止新交易并排空在途事务，确认最后一次写入位置及 Outbox 状态。冻结旧写路径后切到新地址；验证只有一处可写。先做鉴权、Ticket、心跳、送礼和秒杀探针，再核对每笔订单、流水、Outbox 和库存，逐步恢复流量。
3. 恢复流量前如果失败，关闭新写路径并核对无新业务写入后才回退路由。已有新提交时先停写，定位差异、完成同步或受控重放，再决定回退；不得直接打开未包含新提交的旧主。MQ 安全确认条件不足时保留 Outbox，禁止降低副本要求。Redis 不以旧主缓存覆盖数据库权威库存。

## 异机放行记录

独立压测机记录 UTC 与时钟偏差、版本、运行配置和原始日志。按 [容量验证](../load-tests/README.md) 分别跑 API、长连接、广播、交易，再跑同房间混合流量；所有结论附上实例数、CPU、JVM、连接池、限制和同档资源曲线。统计成功、拒绝、限流、系统错误、掉线、未完成订单；429 不计入成功业务容量。

在稳态时逐项演练单宿主机或单故障域失效，分别记录首次失败、首次恢复、业务恢复和积压清空时间。待旧节点恢复并回到正确角色，比较故障前后订单、流水、Outbox、库存与 Redis 派生数据。每次演练留存实际 RTO 与数据差异；跨宿主机未执行时标记未验收，不用同宿主机 Compose 结果替代。
